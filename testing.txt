Traffic Flow Simulation - Testing

========================================
Alpha Release Testing (Lab 30)
========================================


Test 1: File Input

Purpose:
    Check if loadTraffic() correctly reads vehicle data from traffic.txt.

Test:
    Run the program using the 12 vehicle records in traffic.txt.

Expected Result:
    The program should load three roads: Main_Street, Oak_Road, and Park_Avenue.
Each road should initially contain 2 cars, 1 truck, and 1 bus, for a total of 4 
vehicles.

Actual Result:
    Passed. The program successfully loaded all 12 vehicle records from 
traffic.txt. All three roads showed the correct vehicle counts.


Test 2: Vehicle Entry

Purpose:
    Check if simulateTraffic() can add vehicles to the correct road and vehicle 
list.

Test:
    Run the simulation and observe the messages when new vehicles are added.

Expected Result:
    When a vehicle enters a road, the number of vehicles in the selected category 
should increase by 1.

Actual Result:
    Passed. New vehicles were added to the roads during the simulation. 
The vehicle counts increased correctly.


Test 3: Vehicle Exit

Purpose:
    Check if simulateTraffic() correctly removes vehicles from a road.

Test:
    Run the simulation and observe the messages when vehicles leave.

Expected Result:
    When a vehicle leaves a road, the number of vehicles in the selected category 
should decrease by 1. The program should not remove vehicles from an empty list.

Actual Result:
    Passed. Vehicles were removed from the roads correctly. The counts decreased 
by 1, and the program did not remove vehicles from empty lists.


Test 4: Time Periods

Purpose:
    Check if the simulation runs for the correct number of time periods.

Test:
    Run the simulation and check the time period numbers.

Expected Result:
    The program should display Time Period 1 through Time Period 30 and show the 
updated traffic conditions after each period.

Actual Result:
    Passed. The simulation ran from Time Period 1 to Time Period 30. The traffic 
conditions were displayed after each period.


Test 5: Final Traffic Conditions

Purpose:
    Check if displayTraffic() correctly displays the final traffic conditions.

Test:
    Compare the displayed vehicle counts with the entry and exit events during 
the simulation.

Expected Result:
    The total number of vehicles should equal the initial number plus successful 
entries minus successful exits. All vehicle counts should be zero or greater.

Actual Result:
    Passed. The final vehicle counts matched the changes during the simulation. 
No negative vehicle counts appeared.


========================================
Beta Release Testing (Lab 31)
========================================


Test 6: Extended File Input

Purpose:
    Check if loadTraffic() can correctly read 120 vehicle records from 
traffic.txt.

Test:
    Run the program using the updated traffic.txt file containing 120 records 
across 6 roads.

Expected Result:
    The program should load 6 roads. Each road should contain 12 cars, 5 trucks, 
and 3 buses, for a total of 20 vehicles. The total number of vehicles should be 
120.

Actual Result:
    Passed. The program successfully loaded all 120 vehicle records. All 6 roads 
showed the correct initial vehicle counts.


Test 7: Simulation with Extended Data

Purpose:
    Check if simulateTraffic() works correctly with the larger traffic data file.

Test:
    Run the simulation using all 120 vehicle records and observe the traffic 
changes.

Expected Result:
    The simulation should run for 30 time periods. Vehicles should enter and 
leave the 6 roads, and the traffic counts should update correctly.

Actual Result:
    Passed. The simulation ran through all 30 time periods with 6 roads. Vehicle 
entry and exit events worked, and the traffic counts updated correctly.


Test 8: Unique Vehicle IDs

Purpose:
    Check if newly added vehicles receive unique IDs.

Test:
    Run the simulation and observe the IDs of newly added vehicles.

Expected Result:
    Each new vehicle should receive a different ID. The IDs should increase in 
order, starting from NEW1.

Actual Result:
    Passed. All newly added vehicles received unique IDs in increasing order.


Test 9: Vehicle Type IDs

Purpose:
    Check if newly added vehicles receive IDs based on their vehicle types.

Test:
    Run the simulation and observe the IDs of newly added cars, trucks, and buses.

Expected Result:
    New cars should start from CAR73, trucks from TRUCK31, and buses from BUS19. 
Each vehicle type should have its own increasing ID counter without duplicates.

Actual Result:
    Passed. New vehicles received the correct CAR, TRUCK, and BUS prefixes.
Each vehicle type had its own increasing ID counter without duplicates.


Test 10: Traffic Display Format

Purpose:
    Check if displayTraffic() shows traffic data in a clear table format.

Test:
    Run the simulation and observe the initial, updated, and final traffic 
conditions.

Expected Result:
    The program should display road names, cars, trucks, buses, and total 
vehicles in aligned columns. The values should update correctly after each time 
period.

Actual Result:
    Passed. All 6 roads were displayed in aligned columns. The traffic counts 
updated correctly, and the final table matched the results from Time Period 30.


Test 11: Vehicle Exit Information

Purpose:
    Check if simulateTraffic() displays the correct vehicle ID when a vehicle 
leaves a road.

Test:
    Run the simulation and observe the vehicle exit messages. Compare the 
removed vehicle IDs with the vehicle types and traffic counts.

Expected Result:
    Each exit message should show the ID of the removed vehicle and its road. 
The vehicle count for the selected type should decrease by 1.

Actual Result:
    Passed. Vehicle exit messages displayed the removed vehicle IDs and road 
names. The traffic counts decreased correctly.


Test 12: Vehicle ID Formatting

Purpose:
    Check if newly generated vehicle IDs use the same format as the initial 
vehicle IDs.

Test:
    Run the simulation and compare the IDs of newly added vehicles with the IDs 
loaded from traffic.txt.

Expected Result:

at least three digits. New vehicles should start from CAR073, TRUCK031, and

Actual Result:
    Passed. Newly generated vehicle IDs used the correct prefixes and 
three-digit formatting.


Test 13: Grand Total Calculation

Purpose:
    Check if displayTraffic() correctly calculates the total number of vehicles 
across all roads.

Test:
    Run the simulation and compare the Grand Total with the sum of the vehicle 
counts from all 6 roads.

Expected Result:
    The initial Grand Total should be 120. After each time period, the Grand 
Total should match the sum of all road totals. The final Grand Total should 
match the total from Time Period 30.

Actual Result:
    Passed. The initial Grand Total was 120. The totals updated correctly during 
the simulation, and the final Grand Total matched Time Period 30.


Test 14: Empty List Handling

Purpose:
    Check if simulateTraffic() handles an empty vehicle list without errors.

Test:
    Temporarily replace traffic.txt with one vehicle record and run the 
simulation. Observe what happens when the program tries to remove a vehicle from 
an empty list.

Expected Result:
    The program should display a message when the selected vehicle list is 
empty. It should not crash or remove a vehicle from another list.

Actual Result:
    Passed. The program displayed a message when there was no vehicle to remove 
and continued running without errors. The original 120-record input file was 
restored after testing.

input file or previously generated during the simulation.

Actual Result:
    Passed. The program generated unique vehicle IDs using a set. No duplicate

changing an existing vehicle ID to CAR150.

Expected Result:

Actual Result:
